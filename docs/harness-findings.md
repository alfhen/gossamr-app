Two things about the setup itself:

- **Agents must not inherit a Claude Code session's variables.** The first Claude runs, started from inside this Claude Code session, carried `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_ENTRYPOINT=claude-desktop`, a messaging token and account ids into the child `claude` (its MCP user agent read `claude-desktop`, and it emitted `post_turn_summary` and `task_summary` events that a clean run does not). The driver now removes `CLAUDE*`, `ANTHROPIC_*`, `MCP_*`, `AI_AGENT`, `CODEX_*` and `OPENAI_*` before it starts an agent, and every Claude fixture was run again that way (user agent `claude-code/2.1.330 (sdk-cli)`). The harness, started by the app, must build an agent's environment from the person's shell the same way, never from its own.
- **The CLIs write their own per-session state on the real login.** That is not avoidable on a real run and was not removed, since removing it writes to those folders: `~/.claude/projects/<cwd as a path>/<session>.jsonl` and shell snapshots; `~/.codex/sessions/2026/11/22/rollout-*.jsonl` (66 files), its SQLite files, `shell_snapshots/` and `session_index.jsonl`; `~/.gemini/antigravity-cli/conversations/<session id>.db` (a SQLite file of about 450 KB per session) and logs. `codex delete --force <thread>` and `claude purge <path>` remove a session's files.

## A write into a login folder (Codex)

`codex app-server` 0.171.0 writes project trust into `$CODEX_HOME/config.toml` when a thread is started with a sandbox: the `sandbox` field of `thread/start`, or a `sandbox_mode` config override. In check 2 it created `~/.codex/config.toml` holding `[projects."$SCRATCH/clone"] trust_level = "trusted"`. The file did not exist before and held only that entry; it was removed. `spikes/acp/scripts/codex-trust-probe.sh` reproduces it in empty scratch homes. A sandbox on `turn/start` (`sandboxPolicy`), `exec -s` and every ACP mode do not write it. **The Codex driver must never pass a sandbox on `thread/start`.** Two fixtures (`codex/{exec,app-server}/2-permission-escalate`) ran while that entry existed and do not show the person's default.

## Where the docs and the binaries differ

- **Claude** `--permission-prompt-tool` is not in `claude --help` 2.1.330, though `--permission-prompts` names it and it works (`stdio` sends `can_use_tool` on stdout). `--restricted`, `--safe-mode` and `--bare` are new since the findings in `agents-cli-findings.md`; none was used. A foreground `sleep N` is refused by the CLI itself, and long commands are moved to background tasks on the model's choice; neither is in the headless docs.
- **Claude ACP**: the docs present the adapter as a way to run Claude Code; the code shows it runs the Agent SDK's bundled CLI unless `CLAUDE_CODE_EXECUTABLE` is set, and passes its own permission mode and tool flags.
- **Codex**: the app-server README says `item/commandExecution/requestApproval` comes for a "managed requirements.toml prefix rule with decision prompt-user"; in 0.171.0 it came for every command under approval `untrusted`, and for an escalation under `on-request`. `exec` refuses `approval_policy="untrusted"` ("no longer supported"), which app-server still takes. `item/tool/call` (client-declared tools) is in the schema, but `ThreadStartParams` has no field to declare them.
- **agy**: the headless docs show stream-json without `-p`; `-p` before `--input-format` is refused. `agy acp --help` lists `--login`, `--gemini-dir`, `--app-data-dir` and `--process-per-session`, which the ACP page does not describe. No `mcpCapabilities` in `initialize`, yet `session/new` takes an HTTP MCP server and uses it. The headless docs say an action that needs approval is soft-denied; in the stream runs edits and `ls` ran unasked (`permission_mode: request-review`). `--mode auto` is refused for a Google AI Pro account.
- **ACP**: the agents speak protocol v1 with `session/load` and the unstable `session/resume`; the v2 migration (`session/resume` with `replayFrom`) is not offered by any of them.

## Decisions

Section 5 of the proposal names three "stop" rows. None failed: Claude's own setup is honoured on its native path, its locked profile holds, and every provider can be driven on the owner's login.

What each driver must do, from the rows above:

- **Claude.** Build the environment from the person's shell, never the harness's own (drop `CLAUDE*`, `ANTHROPIC_*` and the like). Set the tools endpoint's `timeout` to more than the `ask` wait (600000 ms held 540 s; the default cuts at 60 s). Put the token in a variable named in the header (`${VAR}`), never in argv, and accept that the agent's commands can read it, as they can read today's 0600 file. On a harness restart, stop the orphaned `claude` by pid and start time first: it outlives its client and finishes the turn alone. Expect a session with a background task not to exit on stdin EOF.
- **Codex.** Never pass `sandbox` on `thread/start` or a `sandbox_mode` override. Pass no approval policy or sandbox for normal runs (rule 4); expect read-only in an untrusted clone and say so. Send the token in `http_headers` and set `tool_timeout_sec = 600`. An interrupt does not stop a running command: Stop must also stop the process tree. app-server dies with its client, so a restart resumes by thread id and the cut turn is lost.
- **Gemini.** Pass the tools endpoint in `session/new` `mcpServers` with the token in `headers`; a workspace `.agents/mcp_config.json` is not offered to the model in an untrusted workspace. A deny ends agy's turn with no reply, so the run reads as "stopped after a deny", not as done. Expect GET requests without the Authorization header and answer them 401 without counting them as abuse. Choose the model with `session/set_config_option` (`model`, `thought_level`). An MCP call is cut at 180 s with no setting on this path, so `ask` must give back before then (as Codex did before `tool_timeout_sec`), and the answer comes by resuming the session.
- **All providers.** Commit signing that needs a person (1Password) fails unattended, and agents then turn signing and hooks off by themselves. A run should report that instead of working around it; the guard can say so.

- **Two Google logins side by side.** The owner signs a second account into a scratch home (`HOME=<scratch> agy`), then `agy models` in both homes at once must show each account. agy's credential is not in `~/.gemini/oauth_creds.json` (the old `gemini` CLI's file); find where it is without reading it.

- **How long `claude` waits on stdin EOF with a background task running.** It was killed after 20 s; a run with a longer wait would tell.
- **A real wave through the Workflow tool.** Only listed, as the task said.
